# boundary-chart

A step-by-step exposition of mathematics in James boundary arithmetic, from the void toward F₁, as a chart of laws. One law per file; back-links are the rules each derivation cites; everything else is computed.

- `SPEC.md` — v2.0 (2026-10-13): the data model, the node format, the settings and readings, the engine and its ledgers, status and price, gaps, scope, the process (adding a law, a rung, a setting; iterating the spec) and the decisions register. Stated once, in force; the history is in this file's Status and in ROADMAP.
- `LEGISLATION.md` — the binding decisions, numbered, with a register of what is decided and what is pending.
- `docs/plans/<rung>.md`, `docs/referee/<rung>.md` — a rung's plan as sent before building, and its referee report with the repairs (from rung `H` on).
- `ROADMAP.md` — the path from the classical algebra to the F₁ / motivic / Berkovich pictures, the rung order (LEGISLATION 29) and the rungs as built.
- `references/` — James 1993, the ground truth for the classical setting.
- `nodes/<rung>.<slug>.md` — one law each. Open `nodes/` as an Obsidian vault to get the graph view.
- `concepts/<slug>.md` — one paragraph per concept (optional; the index is computed from nodes' `concepts:` fields).
- `census/` — the small-form census (generated) and the hand-kept list of open forms.
- `tools/` — `check.py` (the engine), `build.py` (the site), `census.py`, `forms.py` (parser + ℂ evaluator), `nodes.py` (file parser), `prover.py` and `licences.py` (the derivation checker), `j1.py` (the receipt prover), `place.py` and `placeledger.py` (the reading at a finite place and the place ledger), `quat.py`, `quatplace.py` and `hledger.py` (the ℍ reading at ∞ and at the places, and the quaternion ledgers), `models/` (witnesses for meta theorems).
- `site/index.html` — generated; the pilot chart.

## Use

```
python3 tools/check.py      # must exit 0 before any node is marked `verified: engine`
python3 tools/build.py      # regenerates site/index.html
python3 tools/census.py     # regenerates census/size-le-3.md and lists unassigned forms
```

No dependencies beyond Python 3.

## Adding a law

1. Copy the nearest node file; give it the next free `order` in its rung (spaced by 10) and an `id` of the form `<rung>.<slug>` that matches the filename.
2. Write the `law:` in canonical `( ) [ ] < >` strings (sugar `o`, `□`, `J`, `void` is accepted; from rung `H` the ordered square `[x ; y]` and the constants `i`, `j`, `k`, `Jj`) and the `units:` in standard notation (a conditional law's `units:` opens with `PREMISE …`); add a `gloss_check:` Python expression where the ℂ value can be stated.
3. Write the Given–Rule derivation as a table whose first column is a form and whose second column cites the licensing node as `[[id]]` (or `given`, `medium`, `congruence`, `substitution`, `definition`, `name` for a standard-notation naming row). Set `uses:` to exactly the ids cited anywhere in the Derivation section — the checker enforces it.
4. Fill the `holds:` (per setting) and `readings:` (per reading) tables; `untested` is a legal cell, a blank is not.
5. Run `tools/check.py`. A theorem becomes `verified: engine` only when it passes — every step value-equal in ℂ *and* licensed by the rule it cites (the derivation checker, `tools/prover.py`; `python3 tools/licences.py --verbose` shows which rule, in which orientation, at which position, took each row to the next).
6. Run `tools/build.py` and look at the card.
7. A law over every n is a `type: schema` node (SPEC §3.7): write the law and the form cells as templates (`A^{n}`, `o^{2k}`, `Σ{j=1..n: …}`), give `schema_range:` (e.g. `n=2..8` or `n=1..6; k=1..n`), head the base-case table `| form (n = 1) | rule | note |` (the base must be the first value of the range), and let the step's `hypothesis` row cite `[[N.induction]]`. The engine checks the base at its value, the step at every other value in the range, and that the hypothesis row is the law at a smaller parameter; the status is `NATIVE-BY-SCHEMA`.
